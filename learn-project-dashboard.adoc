= Workload Factory for EDA のプロジェクトダッシュボードについて説明します
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
プロジェクトダッシュボードを使用すると、IT 管理者とプロジェクトマネージャーは、FSx for ONTAP ファイルシステムとボリューム全体でプロジェクトがストレージをどのように使用しているかを確認できます。ストレージの使用パターンを表示することで、最も多くのリソースを使用しているプロジェクトを特定し、コストを追跡し、容量やパフォーマンスの問題が EDA シミュレーションに影響を与える前にストレージを調整できます。



[[how-the-projects-dashboard-works]]
== プロジェクトダッシュボードの仕組み

プロジェクトダッシュボードには、AWS認証情報にリンクされているすべての ONTAP 用 FSx ボリュームの CloudWatch メトリクスが表示されます。AWS タグを使用して最大 5 つのフィルタを作成し、プロジェクト、チーム、アプリケーション、またはその他のカテゴリ別にデータを整理および表示できます。

ダッシュボードは以下のことに役立ちます：

* キャパシティを計画し、コストを理解する
* データを使用してリソースの割り当て方法を決定する
* 多くのリソースを消費するプロジェクトを特定する
* プロジェクトまたはチームごとにコストを追跡する
* 問題が発生する前にストレージを調整する


プロアクティブなレイテンシパフォーマンス監視については、link:learn-latency-monitoring.html["レイテンシ監視について学ぶ"]をご覧ください。



[[cloudwatch-metrics-collected]]
=== CloudWatch メトリクスが収集されました

ダッシュボードは以下のCloudWatchメトリックを収集して表示します：

* *プロビジョニング済み容量*：プロビジョニングされたストレージ容量を表すボリュームレベルのメトリック。
* *使用容量*: 使用されているストレージを表すボリュームレベルの指標。
* *平均/最大スループット*：指定された期間におけるDataReadBytesとDataWriteBytesの合計の平均または最大として計算されます。
* *平均/最大IOPS*：指定された期間におけるDataReadOperations、DataWriteOperations、およびMetadataOperationsの合計の平均または最大値として計算されます。




[[custom-filters]]
== カスタムフィルター

カスタムフィルターを使用すると、組織の業務プロセスに合わせてダッシュボードのデータを整理できます。プロジェクト、チーム、またはコストセンターごとにフィルターを設定することで、無関係な情報を選別することなく、必要なデータをすばやく見つけることができます。これにより、生産能力の計画、コストの追跡、およびパフォーマンスの監視が容易になります。

AWSタグに基づいて、最大5つのカスタムフィルターを設定できます。

* *フィルターラベル名*：ダッシュボードに表示される表示名
* *AWS タグキー名*：リソースで実際に使用されている AWS タグキー
* *選択タイプ*：単一選択または複数選択


カスタムフィルターを設定しない場合でも、デフォルトのフィルター（ファイルシステム、ボリュームタイプ、期間）は引き続き利用できるため、ダッシュボードを表示および使用できます。



[[aws-tags]]
=== AWSタグ

AWS タグは、AWS リソースのメタデータです。これらは、プロジェクト、アプリケーション、ビジネスユニットなど、さまざまな方法で AWS リソースを分類するのに役立ちます。

カスタムフィルターを使用するには、プロジェクト、チーム、事業部門などのニーズに合ったタグを FSx for ONTAP ボリュームに AWS タグとして追加してください。

タグ付けの詳細については、 https://docs.aws.amazon.com/whitepapers/latest/tagging-best-practices/what-are-tags.html["タグとは何ですか?"^]および https://docs.aws.amazon.com/resourcegroupstagging/latest/APIReference/overview.html["AWS リソースグループタグ付け API リファレンス"^]を参照してください。



[[volume-details]]
== ボリュームの詳細

ダッシュボードには、ストレージの指標をさまざまな詳細レベルで分析するのに役立つ表示モードが用意されています。



[[total-view]]
=== 合計ビュー

合計ビュー（デフォルト）には、選択したフィルターに一致するすべてのボリュームの複合メトリックが表示されます。総容量、IOPS、スループットなど、ストレージ全体のパフォーマンスを素早く把握できます。

このビューを使用して次の操作を実行します。

* 全体的な傾向を理解する
* 将来の容量ニーズを計画する
* プロジェクトまたはチーム全体の総リソース消費量に関するレポート




[[volume-view]]
=== ボリュームビュー

ボリュームビューでは、個々のボリュームのパフォーマンスが時間とともにどのように変化するかが表示されます。各指標における上位10件のボリュームを表示します。これにより、どのボリュームが最も多くのリソースを使用しているか、また選択した期間中にそれらがどのように動作しているかを確認できます。

このビューを使用して次の操作を実行します。

* パフォーマンスを低下させている原因を特定する
+
** サイズ変更が必要になる可能性のあるストレージボリュームを特定する
** どのプロジェクトまたはワークロードが最も多くのリソースを使用しているかを確認します






==== 表示されるボリュームメトリック

個々のボリュームを表示すると、ダッシュボードには各指標について、総ボリューム数の中から上位10件のボリュームが表示されます：

* *ボリューム使用容量*：現在使用容量が最も大きいボリュームを表示します。
* *IOPS*：選択した期間中に平均IOPSが最も高かったボリュームを表示します。
* *スループット*：選択した期間中に平均スループットが最も高かったボリュームを表示します。



NOTE: ダッシュボードには、各メトリックの上位10件のボリュームのみが表示されます。ボリュームが10件を超える場合、詳細ビューに一部のボリュームが表示されない場合があります。

複数のメトリクスに同じボリュームが表示される場合、ダッシュボードは凡例に同じ色を使用するため、異なるメトリクス間でそれらのボリュームを簡単に追跡できます。



==== インタラクティブボリュームデータ

グラフにカーソルを合わせると、特定の時点における正確な値が表示されます。これにより、パフォーマンスの変化をイベントや期間に関連付けることができます。詳細なデータは、パフォーマンスの問題を発見したり、最適化が効果的だったことを確認したり、リソースの使用状況を他者に説明したりするのに役立ちます。

グラフ上の任意のボリュームラインにカーソルを合わせると、次の情報が表示されます：

* *ボリューム使用容量*：ボリューム名、その時点での使用容量、および割り当て容量
* *IOPS*：ボリューム名、期間内の平均IOPS、および期間内の最大IOPS
* *スループット*：ボリューム名、期間内の平均スループット、および期間内の最大スループット
