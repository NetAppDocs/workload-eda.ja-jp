= Workload Factory for EDA のプロジェクトダッシュボードについて説明します
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
プロジェクトダッシュボードは、IT管理者とプロジェクトマネージャーがFSx for ONTAPファイルシステムとボリューム全体でのプロジェクトの使用状況を監視および分析するのに役立ちます。これにより、ストレージの使用パターンを可視化し、リソースを大量に消費するプロジェクトを特定し、コストを追跡し、容量やパフォーマンスの問題がEDAシミュレーションに影響を与える前にストレージ割り当てを最適化するのに役立ちます。



== プロジェクトダッシュボードの仕組み

Projectsダッシュボードは、AWSクレデンシャルに関連付けられたすべてのFSx for ONTAPボリュームのCloudWatchメトリクスを収集します。AWSタグに基づいて最大5つのカスタムフィルターを作成し、プロジェクト、チーム、アプリケーションなどの特定のビジネス要件に従ってデータを整理およびフィルタリングできます。

ダッシュボードは以下のことに役立ちます：

* 容量を計画してコストを評価
* リソース配分に関するデータ主体の意思決定を行う
* リソース集約型プロジェクトを特定する
* プロジェクトやチームを横断してコストを正確に追跡する
* 問題が発生する前にストレージ割り当てを最適化する


プロアクティブなレイテンシパフォーマンス監視については、link:learn-latency-monitoring.html["レイテンシ監視について学ぶ"]をご覧ください。



=== CloudWatch メトリクスが収集されました

ダッシュボードは以下のCloudWatchメトリックを収集して表示します：

* *プロビジョニング済み容量*：プロビジョニングされたストレージ容量を表すボリュームレベルのメトリック。
* *使用容量*: 使用されているストレージを表すボリュームレベルの指標。
* *平均/最大スループット*：指定された期間におけるDataReadBytesとDataWriteBytesの合計の平均または最大として計算されます。
* *平均/最大IOPS*：指定された期間におけるDataReadOperations、DataWriteOperations、およびMetadataOperationsの合計の平均または最大値として計算されます。




== カスタムフィルター

カスタムフィルタを使用すると、組織の運営方法に応じてダッシュボードデータを整理できます。フィルタをプロジェクト構造、チーム、またはコストセンターに合わせて調整することで、無関係な情報を参照することなく、必要な特定のデータにすばやくアクセスできます。これにより、容量の拡張計画、コスト追跡、パフォーマンス監視がより効率的になります。

AWSタグに基づいて、最大5つのカスタムフィルターを設定できます。各カスタムフィルターには、以下のコンポーネントが必要です：

* *フィルターラベル名*：ダッシュボードに表示される表示名
* *AWS タグキー名*：リソースで実際に使用されている AWS タグキー
* *選択タイプ*：単一選択または複数選択


カスタムフィルターを設定しない場合は、デフォルトのフィルター（ファイルシステム、ボリュームタイプ、時間範囲）が引き続き使用できるため、ダッシュボードの表示と操作は引き続き可能です。



=== AWSタグ

AWS タグは、AWS リソースのメタデータです。これらは、プロジェクト、アプリケーション、ビジネスユニットなど、さまざまな方法で AWS リソースを分類するのに役立ちます。

カスタムフィルタを効果的に使用するには、ビジネス要件に基づいて FSx for ONTAP ボリュームに AWS タグを設定します。たとえば、プロジェクト、チーム、または事業部門を表すタグなどです。

タグ付けの詳細については、 https://docs.aws.amazon.com/whitepapers/latest/tagging-best-practices/what-are-tags.html["タグとは何ですか?"^]および https://docs.aws.amazon.com/resourcegroupstagging/latest/APIReference/overview.html["AWS リソースグループタグ付け API リファレンス"^]を参照してください。



== ボリュームの詳細

ダッシュボードには、ストレージの指標をさまざまな詳細レベルで分析するのに役立つ表示モードが用意されています。



=== 合計ビュー

合計ビュー（デフォルト）には、選択したフィルターに一致するすべてのボリュームの集計メトリックが表示されます。このビューには、全体的なストレージパフォーマンスの概要が表示され、容量、IOPS、スループットメトリックの合計が示されます。

このビューを使用して次の操作を実行します。

* 全体的な傾向を理解する
* 将来の容量ニーズを計画する
* プロジェクトまたはチーム全体の総リソース消費量に関するレポート




=== ボリュームビュー

ボリュームビューには、時間の経過に伴う個々のボリュームのパフォーマンスが表示され、各メトリックの上位10件のボリュームが表示されます。このビューは、リソース使用量を増加させている特定のボリュームを識別し、選択した期間にわたるその動作を観察するのに役立ちます。

このビューを使用して次の操作を実行します。

* パフォーマンスのボトルネックを見つける
* サイズ調整が必要なボリュームを特定する
* どの特定のプロジェクトやワークロードが最も多くのリソースを消費しているかを特定します




==== 表示されるボリュームメトリック

個々のボリュームを表示すると、ダッシュボードには各指標について、総ボリューム数の中から上位10件のボリュームが表示されます：

* *ボリューム使用容量*：現在使用容量が最も大きいボリュームを表示します。
* *IOPS*：選択した期間中に平均IOPSが最も高かったボリュームを表示します。
* *スループット*：選択した期間中に平均スループットが最も高かったボリュームを表示します。



NOTE: ダッシュボードには、各メトリックの上位10件のボリュームのみが表示されます。ボリュームが10件を超える場合、詳細ビューに一部のボリュームが表示されない場合があります。

複数の指標で同じボリュームが表示される場合、ダッシュボードは凡例に一貫した色分けを使用して、異なる指標間での特定のボリュームの追跡を容易にします。



==== インタラクティブボリュームデータ

インタラクティブなホバーデータは、特定の時点での正確なメトリックを提供し、パフォーマンスの変化を特定のイベントまたは期間と関連付けるのに役立ちます。この詳細な情報は、パフォーマンスの問題のトラブルシューティング、最適化の取り組みの検証、関係者へのリソース使用パターンの説明に役立ちます。

グラフ上の任意のボリュームラインにカーソルを合わせると、次の情報が表示されます：

* *ボリューム使用容量*：ボリューム名、その時点での使用容量、および割り当て容量
* *IOPS*：ボリューム名、期間内の平均IOPS、および期間内の最大IOPS
* *スループット*：ボリューム名、期間内の平均スループット、および期間内の最大スループット
