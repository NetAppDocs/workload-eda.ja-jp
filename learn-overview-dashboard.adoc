= Workload Factory for EDA の概要ダッシュボードについて説明します
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
概要ダッシュボードを使用すると、IT 管理者は複数の FSx for ONTAP ファイルシステムにわたる EDA ワークロードを 1 か所で監視できます。これを使用すると、システムの健全性や使用状況をすばやく確認したり、新しいボリュームやジョブの配置場所を選択したり、移動が必要なボリュームや SVM を見つけたり、容量やスループットを増やすべき時期を確認したりできます。



== 概要

概要ダッシュボードは、設定済みのAWS認証情報に関連付けられたすべてのFSx for ONTAPファイルシステムのCloudWatchメトリクスを収集します。

内容は以下の通りです：

* *クラスターの健全性ステータス*：上部の概要には、レイテンシイベント、SSDの使用状況、容量の推奨事項、およびファイルシステム全体にわたる ONTAP EMSイベントが表示されます。
* *クラスターテーブル*：各クラスターの使用状況とパフォーマンスを表示する検索可能なテーブル。データのフィルタリングや並べ替え、ページ間の移動、CSV ファイルとしてのエクスポートが可能です。


これはあなたに役立ちます：

* 新しいボリュームを配置し、ワークロードのバランスを再調整する
* 容量またはスループットの拡張を計画する
* 大規模なクラスターの健全性を監視する
* ボリューム配置について十分な情報に基づいた意思決定を行う
* 容量限界に近づいているクラスタを特定する




== ダッシュボードコンポーネント



=== クラスタのヘルスステータス

クラスターの状態は、選択したファイルシステム全体のアクティビティを簡単に確認できる機能です。これは、少なくとも 1 つの FSx for ONTAP リンクがファイルシステムに接続されている場合にのみ表示されます。

健康ステータスには、次の領域が含まれます。

*レイテンシ*:: 選択したファイルシステムで検出されたレイテンシイベントの数を表示します。この情報は、レイテンシ監視が有効になっている場合にのみ表示されます。
*SSD 容量管理*:: SSD使用率が80%を超えるファイルシステムの数と、アクティブな容量推奨値を持つファイルシステムの数を表示します。これにより、容量の見直しが必要となる可能性のあるファイルシステムを迅速に特定できます。
*ONTAP イベント*:: 検出されたEMSイベントの数を、容量、可用性および保護、セキュリティおよびその他に分類して表示します。




=== クラスタテーブル

クラスターテーブルには、アクティブなリージョンとAWSアカウントの選択に基づいてフィルタリングされた各FSx for ONTAPファイルシステムの詳細なビューが表示されます。データはCloudWatchメトリックから収集されます。

この表を使用して次の操作を実行します：

* 容量制限に近づいているファイルシステムを特定する（SSD使用率列）
* プロビジョニングされたスループット SKU とスループット需要を比較します（スループット使用量 P99 列）
* 複数のクラスタ全体でパフォーマンス指標を追跡
* リンク設定ステータスの確認（関連リンク列） - 接続の有効性は毎日検証されます
* パラメータを一括更新する複数のクラスタを選択してください




== SSD容量管理



=== 管理モード

*自動化*:: Workload Factoryは、使用量が設定された制限に達すると、自動的にSSDの容量を追加します。これは自動的に処理されるため、手作業は必要ありません。これは、自動管理を好む環境に適しています。
*推奨*:: Workload Factoryは、SSDの使用状況を分析し、容量を増やすべきタイミングを提案します。これらの提案を検討し、適用するかどうかを決定します。これにより、自動分析のメリットを享受しながら、容量変更を完全に制御できます。
*なし*:: このシステムは、容量に関する推奨事項を提供したり、自動的なアクションを実行したりすることはありません。容量を自分で管理したい場合は、このオプションを使用してください。




=== 容量に関する推奨事項

Workload Factory が自動化モードまたは推奨モードの場合、各 FSx for ONTAP ファイルシステムを自動的にチェックし、容量推奨アルゴリズムを実行します。システムは 24 時間ごとにスキャンを実行し、SSD の容量を調整する必要があるかどうかを確認します。

推奨事項が特定された場合：

* Workload Factoryの通知設定に基づいて、即座に通知が届きます。
* **Last SSD increase timestamp**または**Last SSD increase description**列を使用してClustersテーブルをフィルタリングすることにより、推奨事項のあるファイルシステムを特定します。
* インターフェースには、現在有効な推奨事項があるファイルシステムの総数が表示されます。


推奨事項では、提案された変更とその理由について説明しています。例：_ファイルシステムSSDの使用パターンに基づいて、SSDのサイズを増やすことを推奨します。_



=== SSD管理パラメータ

パラメータは、容量管理システムがSSDの使用状況を分析し、それに基づいてどのような動作を行うかを制御します：

*しきい値*（10～90％）:: SSDの使用率のうち、容量推奨や自動化アクションがトリガーされる割合。例えば、しきい値が80%の場合、SSDの使用率が80%に達したときに推奨事項やアクションが実行されます。この設定は、推奨モードと自動化モードの両方で利用可能です。
*Lookback*（1～200時間）:: 過去のSSD使用パターンを分析するために使用される期間。ルックバック期間が長いほど、容量に関する意思決定のための履歴コンテキストが多く提供されます。Automateモードでのみ使用できます。
*Ahead*（1～200時間）:: 将来の容量ニーズを予測するために使用される期間。先行期間が長いほど、容量の拡張に向けてより先の将来を計画します。Automateモードでのみ使用できます。


これらのパラメータは、ファイルシステムごとに個別に設定することも、一括編集機能を使用して複数のファイルシステムに同じ設定を適用することもできます。



=== 容量に関する決定ポイントについて

SSD使用状況グラフは、システムが容量に関する推奨事項を提示したり、自動的なアクションを実行したりした時点を示します。これらのマーカーは、容量管理アルゴリズムが時間の経過とともにどのように動作したかを示しています。

*推奨事項の決定ポイント*:: システムがSSDの容量追加が必要であることを検出した際に表示されます。容量が増加されていない場合、これらのポイントは30分ごとに表示される可能性があります。グラフには、可能な限り各決定ポイントが表示されます。選択した時間範囲が密集しすぎている場合、ポイントはグループ化されます。
*自動化の意思決定ポイント*:: 自動化システムがSSD容量を増やそうとした際に表示されます。アクションが成功したか失敗したかを示します。


SSD使用履歴グラフを使用して、次の操作を実行できます。

* ストレージサイズを変更する必要がある頻度を確認してください
* 自動化モードと推奨モードのどちらがご利用パターンに適しているかを判断してください。
* 繰り返し発生するストレージ不足を特定する
* 将来のストレージニーズを、時間の経過に伴う成長に基づいて計画します。
* 自動化の試みが失敗した理由を調査する
