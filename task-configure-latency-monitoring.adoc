= Workload Factory for EDAでレイテンシ監視を設定する
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
FSx for ONTAP ボリュームパフォーマンスを追跡するために、読み取りおよび書き込みレイテンシの警告およびクリティカル制限を設定します。メールまたは Amazon SNS アラートを有効にして、レイテンシの問題が発生した際にリアルタイム通知を受け取ることもできます。



[[before-you-begin]]
== 開始する前に

レイテンシー監視を設定する前に、以下の要件を満たしていることを確認してください。



[[aws-credentials-and-permissions]]
=== AWS の認証情報と権限

読み取り / 書き込み権限を持つAWS認証情報をWorkload Factoryに追加する必要があります。レイテンシ監視機能では、AWS認証情報に関連付けられたすべてのFSx for ONTAPボリュームのCloudWatchメトリクスへのアクセスが必要です。

レイテンシ監視では、_Basic_モードおよび_Read-only_モードの権限はサポートされていません。

AWS認証情報を設定していない場合は、link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["AWS認証情報を追加する"^]を参照してください。



[[fsx-for-ontap-file-system]]
=== FSx for ONTAPファイルシステム

AWS 環境にデプロイされたボリュームを持つ少なくとも 1 つの FSx for ONTAP ファイルシステムが必要です。



[[link-to-fsx-for-ontap]]
=== FSx for ONTAP へのリンク

基本分析でコンポーネントの内訳を表示するには、FSx for ONTAP ファイルシステムにリンクを関連付ける必要があります。リンクがなくても、レイテンシ、IOPS、スループットのグラフを表示することは可能です。リンクがまだ関連付けられていない場合は、EDA で「リンクの関連付け」を選択し、新しいリンクを作成するか既存のリンクを関連付けるかを選択してから、「続行」を選択すると、Storage workloads のリンク作成ページに自動的に移動します。

リンクの作成と関連付けの手順については、link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["リンクを作成"^]を参照してください。



[[turn-on-ai-settings]]
=== AI設定をオンにする

アカウント管理者がAI機能を無効にしている場合、メッセージが表示され、AI分析を使用できなくなります。管理者に問い合わせるか、link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["AI管理について学ぶ"^]を参照してください。



[[notification-configuration-optional]]
=== 通知設定（オプション）

レイテンシーイベントが検出された際にメールまたはAmazon SNS通知を受信するには、Workload Factoryの設定で通知設定を構成してください。詳細については、<<レイテンシ通知を設定する>>を参照してください。



[[configure-latency-thresholds]]
== レイテンシしきい値を設定する

読み取りと書き込みの警告レベルおよびクリティカルレベルを設定します。システムはこれらの制限値を継続的に監視し、制限値に達するとアラートを送信します。


NOTE: 重大イベントのしきい値を警告しきい値よりも高く設定してください。そうしないと、設定を保存できません。


NOTE: EDAで設定したレイテンシのしきい値は、デフォルトではアカウント全体に適用されます。また、一般ストレージワークロードで個々のボリュームのレイテンシしきい値を設定することもでき、そのボリュームの設定は当該ボリュームに対して優先されます。EDAでアカウントレベルのしきい値を更新しても、ボリュームレベルの設定は変更されません。

.手順
. 次のいずれかを使用してログインします link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["コンソール体験"^]。
. メニューimage:workloads-menu-icon.png["ハンバーガーメニューアイコン"]を選択し、*EDA*を選択します。
. *レイテンシ*タブを選択します。
. EDAレイテンシ設定ページで、以下のしきい値を設定します：
+
** 読み取りレイテンシ（警告および重大）
** 書き込みレイテンシ（警告および重大）
** 各IOPSのしきい値
** 評価の期間


. *適用*を選択して設定を保存します。


.結果
Workload Factory は、お客様の AWS 認証情報にリンクされているすべての FSx for ONTAP ボリュームのレイテンシメトリックを収集します。設定したしきい値を超えたボリュームは、レイテンシイベントテーブルに表示されます。



[[configure-latency-notifications]]
== レイテンシ通知を設定する

高遅延が検出された際にアラートを受け取るには、メールまたはAmazon SNS通知を設定してください。通知頻度は、以下の2つの方法で制御できます：

* *毎日通知する（推奨）*：ファイルシステムで新たな侵害が発生した際に通知を受け取ります。ファイルシステムに関する通知を送信した後、同じファイルシステムに対して再度通知を送信する前に24時間待機してください。
* *レイテンシ違反が発生した場合の通知（20分ごと）*：違反が検出された場合、最大で20分ごとに1回通知を受け取ります。


レイテンシ通知はファイルシステムごとに送信されます。ファイルシステム内の1つ以上のボリュームがレイテンシのしきい値を超えると、影響を受けるすべてのボリュームを一覧表示する単一の通知が届きます。


NOTE: 影響を受けるボリュームが10個を超える場合、メールには最初の10個のボリュームが表示され、さらに影響を受けるボリュームの数が表示されます。影響を受けるすべてのボリュームは、Workload Factoryコンソールで確認できます。

通知チャネル：

* *メール*：Workload Factoryの通知設定で設定されているメールアドレスに送信されます。
* *Amazon SNS*：他のシステムとの統合のために、設定済みのSNSトピックに公開されます


通知を有効にするには、link:https://docs.netapp.com/us-en/workload-setup-admin/configure-notifications.html#wf-console-email-notifications["通知を設定する"]を参照してください。



[[manage-latency-configuration]]
== レイテンシ設定を管理する

設定後、しきい値はいつでも変更できます。

.手順
. *Latency* ページで、*Edit* を選択します。
. 必要に応じて、しきい値を変更します。
+

NOTE: クリティカルしきい値を警告しきい値よりも高く設定してください。クリティカルしきい値を低く設定すると、システムにエラーが表示されます。

. 変更を保存するには、*適用*を選択します。




[[best-practices]]
== ベストプラクティス

レイテンシー監視を設定する際には、以下の推奨事項を考慮してください：

* *現実的なしきい値を設定する*：作業量に合わせてしきい値を設定してください。デフォルト値はあくまで出発点であり、環境に合わせて調整する必要があるかもしれません。
* *警告しきい値から始める*：まず警告アラートを確認して通常のパフォーマンスを把握し、次にクリティカルな制限を設定します。
* *時間範囲を慎重に検討してください*：短い時間範囲（5～10分）は問題をより早く発見できますが、アラートが多く発生する可能性があります。時間範囲を長くする（15～20分）と誤報は減りますが、問題の発見が遅れる可能性があります。
* *IOPSとレイテンシのしきい値を調整する*：両方の条件を満たす必要があります。IOPS制限が高すぎると、レイテンシが高い場合でもシステムがアラートを送信しない可能性があります。
* *却下されたイベントのレビュー*：イベントが却下された理由を定期的にレビューし、しきい値を調整する必要があるか、システムを改善する必要があるかを確認します。
